# The files where this game's own patches (patches/) or the commits its submodules pin change the same lines as
# N64Recomp-browser's web support: <project> <path in the project>. tools/build_web.sh leaves each out of
# N64Recomp-browser's patch for its project and applies web/patches/<project>.patch in its place, the web's change to
# these files merged by hand on top of the game's. The web's later changes to them are merged in by apply.cmake --since
# from the commit below; one that meets the game's own lines stops the build, for another merge by hand and this
# commit moved. A file followed by own is left to the game alone: the web's change to it is left out, then and later.

# rt64: the game's rt64 is newer than the web's (the texture decoder shared with the CPU in src/shared, GPU timestamps
# that may be missing, the VI rate of uneven frames, file dialogs that answer by callback) and has its camera cuts
# patch (staleWritebacks). The shared decoder calls TMEM's sizes TMEM_RDP_*, the web's shaders RDP_TMEM_*. With
# RT64_UNEVEN_FRAME_RATES (on in a page) the web's rate for uneven frames is used, the game's otherwise. In
# rt64_rsp.cpp the game's patch and the web both mend the box of a triangle with a corner behind the camera, which
# projects to meaningless points (the bar at the bottom of the ice cave): the game's takes it as covering the
# viewport, the web's (rt64 a8bfc93, dd2fd23) as covering the scissor if it crosses the camera plane and as drawing
# nothing if it is wholly behind it. The page keeps the web's, which covers the game's case, and gives the game's N64
# cost estimate (N64 Slowdown) after it the game's behindCamera, a corner behind the camera, from the web's count.
# hlslpp: the game's rt64 pins a newer hlslpp, which shifts each lane by its own count its own way; the web's other
# wasm fixes are kept.
# N64Recomp: the game's own patch writes ops into $zero as the web's assignment() does; the web's is kept.
# RecompFrontend: the game's RecompFrontend saves player assignments next to the web's mappings object. Its controls
# page is upstream's newer, which assigns players on the page itself: the web's change to the page is for upstream's
# older one (Assign players while a multiplayer game plays as single-player mode), and this game keeps single-player
# mode. So profiles.cpp is the game's too after the web's change from the commit below: the web's later changes to it
# are the rules of players assigned in a multiplayer game (whose keyboard each reads, a keyboard player's Reset to
# defaults), which never run in single-player mode and meet upstream's newer Reset to defaults.
